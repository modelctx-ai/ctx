## 2026-10-26

- **新增** [ADR 0005](adr/0005-session-position-writes-format.md)（已采纳，不改代码）：会话位置改用 `seq`（补写旧记录会被摘要盖掉）、写入前提条件 `expectSeq` 和围栏、`recover` 的 `owner`、ctx 自己的带版本 JSON 消息格式（读时升级，部件逐项对照 `ai@7.0.150`）、`AgentSpec.context`、会话分页和事件 `kinds` 过滤；`ctx-sqlite` 结构版本 2 → 3；对内存、sqlite、remote、gateway 的破坏面，和对照 yoyo `main` 代码核对出的 yoyo 影响。
- **修复** harness 加进程内的每会话串行队列（`createHarnessRuntime` 自己维护，只排 `record` 不为 `false` 的运行）：上一个提交让同一进程里不经编排器并发调 `harness.run`、`context.generate` 的第二个运行直接得到 `session_busy`，现在改成等前一个结束再开始，`session_busy` 只出现在跨进程或别的 harness 实例上。排队时 `signal` 中止，这一轮以 `aborted` 结束且什么都不写（前面没人排队时 `signal` 已经中止照旧写 started 和 ended）。流式的一轮在结果落定时才交出位置。编排器自己的队列保留。
- **发布** 所有包（`ctx-protocol`、`ctx`、`ctx-sqlite`、`ctx-remote`、`ctx-gateway`、`ctx-mcp`、`ctx-exec`、`ctx-models`，共八个）0.2.0 → 0.3.0，一起升；包间依赖是 `workspace:^`，不用改。阶段 1 到 5 都有不兼容的改动（`Cursor` 删除、`ModelMessage` 换成 `Message`、`sessions()` 顺序、`append` 的第三个参数……），按 [ADR 0002](adr/0002-packages.md) 升 minor。**不支持滚动升级**：同一个库（`ctx-sqlite` 结构版本 3）和同一组 `ctx-remote` 服务端、客户端的所有进程要先全部停下，再一起升到 0.3；旧版写的行没有 `v`，仍是合法的旧行，新版写的行旧版读不了。升级后用 `findLossySummaries`、`recompactLossy` 修复被旧摘要盖住的条目。
- **更新** [ADR 0003](adr/0003-context-model.md)、[ADR 0004](adr/0004-protocol-and-implementation.md) 按 ADR 0005 修订：消息改用 `Message`，`covers` 和位置用 `seq`，日志顺序和投影顺序分开说，「没有采用：自定义消息格式」一条被推翻；[概念](concepts.md)术语表加消息和版本、`expectSeq`、围栏、`owner`、`ContextSpec`；[ADR 0002](adr/0002-packages.md) 的包数改成实际的八个；[ADR 0005](adr/0005-session-position-writes-format.md) 加实施状态和各阶段的提交。
- **实现** [ADR 0005](adr/0005-session-position-writes-format.md) 阶段 4（`AgentSpec.context`）：协议包加 `ContextSpec`（`facts`、`projection`）、`FactsSpec`（`sources`、`placement`、`heading`），`AgentSpec.context`，`BuildRequest.facts` 放宽成 `boolean | FactsSpec`，`BuildRequest.projection`、`ViewOptions.projection`；`agentSpecToJson` 带上 `context`，`ctx.run.started` 因此记下这一轮的上下文配置。`createContextBuilder` 加 `projections`（按名字注册的投影配置，`default` 缺省取 `projection` 选项，每套是完整的、不合并），`factsPlacement` 成为缺省值；不认识的投影名在 `build`、`view` 里以 `not_found` 失败（先于收事实），没注册的来源名忽略并告警；`LocalContextBuilder.facts` 第三个参数 `{ sources }`。harness 把 `agent.context` 传进 `BuildRequest`（`createContext` 自己收了事实时以它的 `facts: false` 为准）。契约测试：忽略 `context` 的 builder 会在「不认识的投影名」用例失败；核心包另测同一个 builder 上两个 `context` 得到不同的事实、位置、投影。
- **实现** [ADR 0005](adr/0005-session-position-writes-format.md) 阶段 2（`expectSeq`、围栏、`owner`）：`append(session, entries, { expectSeq })`，会话末尾 `seq` 不等于它（空会话 0）时整批不写，抛 `conflict`（`CtxError`，`retryable: true`），检查先于去重；协议包加 `AppendOptions`、`headSeq`、`isConflict`、`conflictError`、`checkExpectSeq`，`CtxError` 加 `retryable`，`RunStartedData.owner`、`RunRequest.owner`。内存存储在同一个同步段里检查；`ctx-sqlite` 的 `append` 改成 `BEGIN IMMEDIATE`（应用已有事务时 SAVEPOINT），先拿写锁再检查；`ctx-remote` 的 `POST …/entries` 带 `expectSeq`，409 映射为 `conflict`。harness（只对 `record` 不为 `false` 的运行）：开始时读最后一个生命周期事件，`started` 就以 `session_busy` 结束且不写；之后每次写入带 `expectSeq`，冲突时自己的 `runId` 已有 `ctx.run.ended` 就是被围栏，以 `aborted` 停下、不再写 ended，否则用新的末尾重试。`createOrchestrator({ owner })`：`recover` 只收同一个 `owner` 的运行，写 `ctx.run.ended` 时带 `expectSeq`，读和写之间会话有新条目就跳过；找到断点的会话才多读一次末尾。用缺省 `record` 的应用启动时要先 `recover` 再 `submit`。契约测试加了 `expectSeq`、`session_busy`、`owner`；另有两个 sqlite 句柄和多进程并发同一个 `expectSeq` 恰好一个成功、被 `recover` 结束的运行下一次写入时停下且不重复写 ended。
- **实现** [ADR 0005](adr/0005-session-position-writes-format.md) 阶段 3（消息格式和版本）：协议包定义 ctx 自己的 JSON `Message`（`MessageContent`、各种部件，覆盖 `ai@7.0.150` 的 `ModelMessage` 全部部件，含 `reasoning-file`、`custom`、`tool-approval-request`、`tool-approval-response`），不再导入 `ai` 的消息类型（只剩 `ModelRef` 里的 `LanguageModel`）；`PreparedCall.messages`、`RunResult.messages`、`RunRequest.input`/`prompt`、投影回调、`textOf`、`estimateTokens` 都换成它。`@modelctx-ai/ctx` 加 `toModelMessages`、`fromModelMessages`（及单条、`UserContent` 的版本）：子集之外的部件抛 `unsupported_part`，harness 把这一轮以 `error` 结束；`createContext()` 仍收 AI SDK 的 `UserContent`，在边界上转。部件类型有编译期的穷尽检查（`AI_SDK_PART_TYPES`）。条目加 `v`（`ENTRY_VERSION = 1`），协议包加 `upgradeEntry(raw)`：存储读时把 v0（0.2 及以前，AI SDK 消息加 `\u0000ctx` 标记，`covers: { at, seq }`）升到当前形状，更高的版本抛 `unsupported_version`，旧行不回写；新行写 `v: 1`。`ctx-sqlite` 的 `v` 列在 schema 3 的 `repairs()` 里补（可重复执行），`\u0000ctx` 编码删掉；`ctx-remote` 的 `wire.ts` 编码删掉（0.2 和 0.3 的客户端、服务端不能混用）；`ctx-gateway` 的 `messages.ts`、`rewrite.ts` 改成收发 `Message`。新增 `findLossySummaries(store, { session? })`（只读，列出 `v` 为 0 且有条目被新规则盖住的摘要）和 `recompactLossy(builder, finding, options)`（追加一条 `covers` 相同的新摘要取代旧摘要，`LocalContextBuilder` 加 `store`、`recompact`）。测试：v0 黄金样例（手写，yoyo 的夹具里只有纯文本）、每种部件互转、harness 遇到 `unsupported_part`、sqlite 旧库读写。版本号和 ADR 0003/0004 的修订留到最后一个阶段。
- **实现** [ADR 0005](adr/0005-session-position-writes-format.md) 阶段 5（分页和 `kinds`）：`sessions(options?: { prefix?, after?, limit? })`，名字升序（码点序，也就是 UTF-8 字节序），内存存储从插入顺序改成名字升序；`ListOptions.kinds` 只返回 `kind` 在其中的事件，与 `types` 取交集，`last` 在过滤之后取。协议包加 `SessionsOptions` 和纯函数 `filterSessions`（`filterEntries` 也认 `kinds`）。`ctx-sqlite` 在 schema 3 这一级加生成列 `kind`（`json_extract(body, '$.kind')`，VIRTUAL）和索引 `(session, kind, seq)`，前缀用范围查询不用 `LIKE`。`ctx-remote` 加 `GET /sessions?prefix=&after=&limit=` 和 `entries?kinds=a,b`（`kind` 里带逗号时客户端报错）。`recover` 改成翻页（每页 100 个会话名），每个会话一次 `list({ kinds: [ctx.run.started, ctx.run.ended], last: 1 })`，不读消息正文；同一会话里被后一个运行盖住的老断点不再补。契约测试加了 `kinds`、`sessions` 的升序和翻页（含 `%`、`_`、`\`、补充平面字符）、会话多于一页的 `recover`。
- **修复** `compact` 的边界：`fold` 合并的事件组里混进补写的旧记录时（`from` ≤ `covers` < `upTo`），整组进摘要会让 `seq > covers` 的成员留在视图里重复，现在 `covers` 退到这一组的 `from` 减 1，整组留在视图里。`ctx-sqlite` 的迁移每一步先查实际的列和索引再补，schema 3 同一级的结构不全（先前的提交建出来的库）也能补齐，可以重复执行。
- **实现** [ADR 0005](adr/0005-session-position-writes-format.md) 阶段 1（位置）：`Cursor`、`compareCursor`、`cursorOf` 删除，`after`、`covers`、`ProjectedMessage.upTo`、`CompactedData.covers` 改成 `seq` 数字（不留别名，这是 0.3 的不兼容改动，版本号在最后一个阶段一起升）；`list`、`watch` 按 `seq` 升序，补写的旧记录排在写入的位置，投影按新的 `compareEntries`（`(at, seq)`）重排；`latestSummary` 在 `covers` 相同时取后写的；`compact` 的 `covers` 取保留条目里最小 `seq` 减 1（`fold` 合并的事件组横跨切点时再退到组的 `from` 减 1），`ProjectedMessage` 加 `from`。内存存储去掉 `insertSorted`；`ctx-sqlite` 结构版本升到 3（这一阶段只换索引：`(session, at, seq)` → `(session, seq)`，旧摘要的 `{ at, seq }` 读成 `seq`）；`ctx-remote` 的 `after.at`/`after.seq` 查询参数合并成 `after`。契约测试加了补写旧记录后的 `list(after)`、`watch(after)`，和 `clear` 后 `seq` 不回退。
- **实现** `ctx-sqlite`：结构版本升到 2，`<prefix>meta.schema` 真正被检查。0.1 的库（`thread` 列）和 0.2 的库（`session` 列，版本同为 1）打开时在写锁里迁移，不用应用自己 `RENAME COLUMN`；比自己新的版本拒绝打开。自己开库时设 `busy_timeout`（`busyTimeoutMs`，缺省 5000），传进来的 `database` 缺省不改。写入从 `INSERT OR IGNORE` 改成 `ON CONFLICT DO NOTHING`，NOT NULL 违例不再被静默吞掉。
- **更新** [协议层](protocol.md)：`ErrorInfo` 加 `statusCode`、`responseBody`（上游 HTTP 接口出错时的状态码和响应正文，纯 JSON，随 `RunResult.error` 过线）。
- **更新** [协议层](protocol.md)、[实践：yoyo](repos.md)：yoyo 的描述跟上 yoyo#9：`createYoyoOrchestrator` 实现 `Orchestrator`，碎碎念和回复是同一个 `createHarness` 跑的两份 `AgentSpec`，导演只剩舞台动作，常驻循环只管进程。
- **实现**：harness 在一轮开始前对「工具绑定的执行环境没交给 harness」告警一次，调用时错误信息列出可用的执行环境；`createOrchestrator` 的 `submit` 在每轮结束后摘掉 `request.signal` 上的 abort 监听。

## 2026-10-25

- **新增** `packages/exec`（`@modelctx-ai/ctx-exec` 0.2.0）：本机子进程 `Executor`。`run_command` 在工作目录里用 shell 跑命令，`read_file`、`write_file`、`list_dir` 只碰工作目录里面（拒绝 `..` 和指出去的符号链接）；环境变量白名单、超时和取消时杀整个进程组、输出截断并注明截掉多少、`allow` 审批；`commands` 把固定命令包成专门的工具。结果是带 `<exit_code>`、`<stdout>`、`<stderr>` 的文字，非零退出码不算错误。
- **新增** `packages/remote`（`@modelctx-ai/ctx-remote` 0.2.0）：协议的 HTTP 形态。服务端 `/server` 的 `startRemote`、`createRemoteHandler` 挂会话存储、执行环境、harness、编排器，安全缺省照网关；客户端只用 `fetch`：`createRemoteSessionStore`（含 `watch`）、`createRemoteExecutor`、`createRemoteHarness`（含 `stream`）、`createRemoteOrchestrator`。四个协议的契约测试都在远程客户端上跑过，另有三服务端到端一例。
- **更新** [协议层](protocol.md)：「线上形态」按实现定稿：编排器移到 `/orchestrator` 下，和 harness 的 `/runs` 分开；加 `DELETE /runs/:runId`（`signal` 跨边界）、`GET /orchestrator/runs/:id?wait=` 长轮询、`POST /orchestrator/recover`、`GET /executors`；编排器事件用 NDJSON 不用 SSE。「托管矩阵」写实际的 API 名，去掉「（计划）」。[概念](concepts.md)里 worker 拉取改成「之后加」。

- **实现**：`@modelctx-ai/ctx` 改成协议的进程内参考实现，五个实现包升到 0.2.0。核心包把协议包当 peer，删掉重复的条目、存储接口、投影、来源、token 估算、工具类型，改为从协议包导入并原样再导出；新增 `createFunctionExecutor`、`createContextBuilder`（`factsPlacement: 'prompt'` 给提示缓存留不变的 system 前缀）、`createHarness`、`createOrchestrator`；`createToolRegistry` 实现协议的 `ToolRegistry`，加 `addTool`、`toolSet`、`toToolSet`；`createContext` 改成组合门面，`generate` 走 harness，结果加 `runId`、`stopReason`，日志里多了 `ctx.run.*`；`compact` 另记 `ctx.compacted`。`thread` → `session`、`ContextStore` → `SessionStore`、`threads()` → `sessions()`，旧名留作弃用别名。
- **实现**：ctx-sqlite、ctx-mcp、ctx-gateway 只依赖协议包。sqlite 的列改名 `session`，加轮询的 `watch`；mcp 的 hub 本身是一个 `Executor`（名字缺省 `mcp`），`registerInto` 写 `ToolDefinition`；gateway 的 `withContext` 也收 `(builder, session)`。
- **新增** 协议包的 `describeHarnessContract`、`describeOrchestratorContract`（工厂收一份模型剧本），核心包的 `/testing` 加 `createScriptedModel`。
